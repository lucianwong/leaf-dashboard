# 2026-09-06 审核补充修复四项

## 做了什么

按第二轮反馈完成四项修复:

1. **Remote Full 在 Unchanged 时也必须执行**:`performEinkFullRefresh` 原来只在 `RefreshResult.Updated` 分支消费,画面无变化时远程全刷指令被静默吞掉。`Unchanged` 分支现在同样消费 `pendingFullRefresh`(Failed 保留待下轮重试)。
2. **configVersion Int → String 升级迁移**:0.2.0 曾以 Int 存储,直接 `getString` 会抛 `ClassCastException` 令同步永远失败。读取处捕获该异常并清除旧值,按未配置处理(触发一次策略重应用)。
3. **cacheDir 根目录 frame_*.png 完整迁移**:0.1.x/0.2.0 所有帧都写在 cacheDir 根。迁移逻辑覆盖:cacheDir 根与 cacheDir/frames 两处来源;`frame_current.png → frame_home.png` 归位;`frame_next_*` 中间态直接删除;其余 `frame_*.png` 原名迁移,迁移后清理旧目录。
4. **Authorization 禁止跨 origin redirect**:`fetchText` 重定向循环比较 `next.origin`(含协议),跨 origin 且请求携带 Authorization 头时直接抛错拒绝;同 origin 重定向放行(逐跳 SSRF 校验不变)。探活路由本就是 `redirect: manual`(3xx=Down),不受影响。

### 新增/修改文件

| 文件 | 变更内容 |
| --- | --- |
| `android/.../MainActivity.kt` | Unchanged 分支消费全刷;configVersion ClassCastException 迁移;cacheDir 全量帧迁移 |
| `server/src/datasources.js` | fetchText 跨 origin 重定向 + Authorization 拒绝 |

### 核心决策

- Failed 时不消费 pendingFullRefresh:网络恢复后的下一轮同步会补执行全刷,指令不丢。
- 跨 origin 一律拒绝(而非剥离 Authorization 继续):这些端点(zai/kimi/codex/custom)正常不会跨 origin 302,遇到即是异常信号,宁可失败告警。
