# 2026-09-06 第三轮审核修复七项(P1×7 + P2×4)

## 做了什么

1. **Safe Mode heartbeat-only**:Safe Mode 不再完全跳过 `pollOnce`——进入 heartbeat-only 路径(上报心跳+保持轮询节奏),设备保持在线可见,Admin 能看到 safeMode 标记。
2. **safeModeUntil 持久化恢复**:废除单个 Handler callback 的恢复机制,改为持久化 `safe_mode_until`(epoch)。判定函数 `isSafeModeActive()`:截止前 heartbeat-only(即使进程被杀重启也依然生效),截止后自动清除并恢复正常同步。
3. **Crash Guard 降误判**:引入 `last_alive_at`(每次同步/心跳更新)与 `startup_reason`。判定链:startupReason=boot/package_replaced → 重置计数(系统性重启非崩溃);上次会话存活 ≥5 分钟(healthy run)→ 重置;仅"间隔 <5 分钟且非 healthy"才计入疑似崩溃。
4. **partialRefresh 真正接入**:`showBitmap`(帧更新显示)现在调用 `eink.partialRefresh(frameView)` 并记录策略 partial;切页路径计入局刷。BOOX 专有快速局刷 API 留真机 Discovery 后接入,当前为标准重绘。
5. **partialRefreshCount 拆分**:`partialRefreshTotal`(总数,永不清零)与 `partialSinceFull`(距上次全刷,整刷执行时清零)两个计数器。
6. **lastFullRefreshAt 执行时更新**:从同步时点移到 `performEinkFullRefresh` 真正执行处(连同 sinceFull 清零),确保只在真正 perform Full 时更新。
7. **Heartbeat 移到 finally**:在全部 metrics 更新之后上报;下载失败等提前返回路径也照常上报。
8. **syncAttempt/success/fail 三指标**:attempt 在拉取 manifest 时计数,成功/失败在收尾分流。
9. **成功清 lastError**:同步成功路径置空 lastError(仅保留最近一次真实错误)。
10. **BOOX capability telemetry**:`einkAvailable`(专有 API 是否命中)+ `einkController`。
11. **einkMode / 实际策略**:heartbeat 同时携带 `einkMode`(控制器模式,当前 normal)与 `lastRefreshStrategy`(最近一次实际策略 partial/full)。
12. 顺带:BootReceiver 写入 startup_reason;服务器/客户端字段名对齐(syncAttemptCount/syncSuccessCount 补进 storage 白名单)。

### 核心决策

- Safe Mode 恢复不依赖 Handler:进程死亡重启后 `isSafeModeActive()` 按 epoch 判定依然正确,heartbeat-only 保证设备不失联。
- 跨 origin + Authorization 组合直接拒绝(而非剥离后继续):这些端点正常不跨 origin 302,异常即失败告警。
