# 2026-09-06 第二轮审核补充修复四项

## 做了什么

1. **帧迁移安全化**:迁移前先 `frameDir.mkdirs()`(rename 依赖目标目录存在);旧文件只有 rename 成功(或 rename 失败回退 copy 成功)后才删除,失败的保留到下次启动重试;旧目录仅在清空后才移除。
2. **refreshSeq/fullRefreshSeq 延迟 commit**:收到信号不再立即持久化——refreshSeq 在强制重拉的当前页成功落地后才写入;fullRefreshSeq 在整刷真正触发后才经 `commitFullSeq()` 写入。任一环节失败,下一轮 manifest 的 seq 仍更大,自动重试。
3. **Admin 设备表列数对齐**:表头 6 列(状态/最后在线拆开),数据行补足 6 格。
4. **Authorization 大小写无关**:`fetchText` 的跨 origin 重定向检查改按 `k.toLowerCase() === "authorization"` 匹配(HTTP 头本就 case-insensitive)。

### 新增/修改文件

| 文件 | 变更内容 |
| --- | --- |
| `android/.../MainActivity.kt` | 迁移 mkdirs 前置+成功才删;`pendingFullSeq` 字段与 `commitFullSeq()`;seq 延迟 commit |
| `server/public/admin.html` | 设备表 6 列对齐 |
| `server/src/datasources.js` | Authorization 头匹配大小写无关 |

### 核心决策

- 全刷 seq 的 commit 点在 UI 线程触发整刷处(触发即视为执行,回退帧法无法失败);阈值/周期型全刷不携带 seq,不受影响。
- Failed 分支不消费 pendingFullSeq:网络恢复后下一轮自动补执行。

## 影响范围

- 客户端需更新 APK(分发已更新);服务端已重启。

## 遗留问题

- 真机项(BOOX 波形/KeyCode/BootReceiver)与文档同步不变。
