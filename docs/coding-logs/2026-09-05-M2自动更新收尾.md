# 2026-09-05 M2 自动更新收尾（失败退避重试 + 回前台恢复轮询）

## 做了什么

Milestone 0+1 已验收，M2（自动更新）的主体（deviceId、status/version API、定时轮询、版本比对下载）在 M1 中已实现。本次补齐 M2 剩余的"网络异常恢复"缺口，仅改 Android 客户端：

1. **失败快速重试**：上一轮刷新失败（无网/超时/服务端错）时，下次轮询由固定 5 分钟改为 30 秒后退避重试，网络恢复后能自动追上；成功/无变化仍按 5 分钟周期。
2. **回前台恢复轮询**：`onPause`/`onStop` 会清空 Handler 回调，原先回到前台后永远不再自动更新（只能手动触屏）。新增 `maybeResumePolling()`，在 `onResume` 中对已完成设置的场景延迟 1 秒重新触发一次 `pollOnce()`（刷新防抖 `refreshInFlight` 天然兜住在途任务，重复触发安全）。
3. **`onStop` 补刀清理**：修复审查备忘中提到的边界——在途刷新完成时若 Activity 已入后台，其完成后仍会重新排队轮询回调；`onStop` 再清一次，避免后台无谓唤醒。

### 新增/修改文件

| 文件 | 变更内容 |
| --- | --- |
| `android/LeafDashboard/app/src/main/java/com/boolwise/leafdashboard/MainActivity.kt` | 新增 `POLL_RETRY_MS`（30s）/`RESUME_POLL_DELAY_MS`（1s）常量；`scheduleNextPoll(delayMs)` 带参化；`onResume` 增加 `maybeResumePolling()`；新增 `onStop()` 清回调；`pollOnce` 结果分支按 Failed/其余选择重试或正常周期；类注释同步更新 |
| `android/LeafDashboard/local.properties` | 本机构建用 SDK 路径（`sdk.dir=~/Library/Android/sdk`），已被 gitignore，不入库 |

### 核心决策

- 不引入指数退避表：单设备内网场景下固定 30s 重试足够简单可靠，避免过度设计。
- 回前台用"延迟 1s 后直接 pollOnce"而非仅重排 5 分钟周期：信息屏场景回到前台即想要最新画面，且与手动刷新同路径（有防抖与即时反馈）。
- 服务端无需改动：version 时间驱动策略已满足 M2 验收要求。

## 影响范围

- 仅 Android 客户端轮询行为；无接口变更，服务端与构建配置不受影响。
- `./gradlew assembleDebug --no-daemon` BUILD SUCCESSFUL（37 任务，5 执行 32 缓存），APK 产物正常生成于 `app/build/outputs/apk/debug/app-debug.apk`。

## 遗留问题

- 失败重试为固定 30s，若服务器长时间不可用会持续每 30s 唤醒一次 I/O（前台常驻信息屏场景影响可忽略；如需省电可后续加指数退避上限）。
- M3（E-Ink partial/full 刷新、BOOX 专有 API 适配）与 M4（物理翻页键多页面）尚未开始，需真机采集 KeyCode 后推进。
