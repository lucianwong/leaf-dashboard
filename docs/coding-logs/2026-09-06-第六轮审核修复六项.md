# 2026-09-06 第六轮审核修复六项

## 做了什么

1. **downloadFrame UI callback 竞态**:`page == currentPage` 判断从 IO 线程移入 `runOnUiThread` 内——IO 判断后、UI 贴图前用户切页,旧页会被贴回导致画面与状态不一致,直至下次刷新。
2. **fullRefreshInFlight 锁**:Generic Full 的白→黑→内容约 300ms 异步窗口内,忽略用户翻页(`switchPage` 直接 return)与手动刷新(`manual && fullRefreshInFlight` 时 return;自动轮询不拦,避免杀死轮询链——300ms 窗口与 5 分钟周期碰撞概率极低)。`AtomicBoolean.compareAndSet` 入口,`onComplete` 释放。
3. **Safe Mode 定时链去重**:safeMode heartbeat-only 分支先 `removeCallbacksAndMessages(null)` 再 `scheduleNextPoll()`,保证始终只有一条定时链(此前 onCreate 的 5min 定时链与 onResume 的 1s 链会双开)。
4. **desiredPage callback 捕获 targetPage**:UI callback 校验 `currentPage == targetPage` 后显示捕获的页,防御 callback 执行前用户又翻页。
5. **下载失败透传真实原因**:新增 `lastDlReason` 字段(markDlFail 记录 sha256 mismatch/decode failed 等具体原因),当前页失败外层 `throw IOException(lastDlReason)`——lastError 不再被 "current frame download failed" 笼统消息覆盖,soak 故障定位可见真实原因。
6. **BUILD_COMMIT 时序修正**:发布脚本改为"先 commit 再重建 APK 再复制分发",APK 内嵌的 buildCommit 指向最终提交(实测 versionCode=124 / buildCommit=7c17388)。

### 新增/修改文件

| --- | --- |
| `android/.../MainActivity.kt` | UI callback 内重验 currentPage;fullRefreshInFlight AtomicBoolean 及三处守卫;SafeMode 分支清回调;desiredPage 捕获 targetPage;lastDlReason 透传 |
| `android/.../AndroidManifest.xml` | 无变化(本轮 receiver exported=false 已在上一批落盘) |

### 核心决策

- Full 窗口只拦"用户交互"(翻页/手动刷新),自动轮询放行:拦自动轮询需要处理轮询链保活,复杂度不值当;300ms 窗口与 5 分钟周期碰撞概率可忽略。
- 发布脚本固化"commit → build → copy"顺序,解决 buildCommit 滞后一个提交的问题。
