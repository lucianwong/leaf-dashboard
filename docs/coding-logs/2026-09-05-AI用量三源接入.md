# 2026-09-05 AI 用量接入 codex / zai / kimi 三源

## 做了什么

把 AI 用量页从"单个通用 JSON 端点"扩展为"多源适配器"结构,接入并实测三家 Coding Plan 用量:

1. **接口调研与实测**(全部 200 通过后才动手):
   - Codex:`GET https://chatgpt.com/backend-api/wham/usage`,`Bearer <access_token>` + `ChatGPT-Account-Id` 双头,凭据读本机 `~/.codex/auth.json`(plain fetch 即可,无 Cloudflare 拦截);返回 `rate_limit.primary/secondary_window.used_percent` + `limit_window_seconds`。
   - GLM(bigmodel.cn/z.ai):`GET /api/monitor/usage/quota/limit`,`Authorization: <key>`(**无 Bearer 前缀**);`data.limits[]` 里 `TOKENS_LIMIT` 即 token 窗口(unit=3 配 number=5 是 5 小时窗,unit=6 是周窗),`TIME_LIMIT` 是 MCP 月度调用不展示。
   - Kimi For Coding:`GET https://api.kimi.com/coding/v1/usages`,`Bearer sk-kimi-…` + UA `KimiCLI/1.6`;`usage` 为套餐摘要,`limits[]` 为滑动窗口,数值全是字符串。
2. `storage.js`:`aiUsageUrl`(string)→ `aiUsage` 列表 `[{name,url}]`,类型白名单 `codex/zai/kimi/custom`,同名去重、最多 6 条;codex 免 URL;旧字段一次性迁移成 custom 源。
3. `datasources.js`:三个厂商适配器 + custom 通用解析,统一产出 `{name,label,plan?,windows:[{label,pct}],text?}`;每源独立 5min 缓存与 lastGood 兜底;codex 401 时用 refresh_token 刷新并原子写回 auth.json(防 refresh_token 轮换丢失导致 CLI 掉登录)。
4. `renderer.js`:AI 页改为每源一行——左标签(+套餐)、右主百分比(取最紧窗口)、黑白条纹进度条、窗口明细行;失败源显示"获取失败"。
5. `admin.html`:AI 用量改为"类型 | URL"多行编辑(复用探活列表的 parseChecks),hint 说明三家凭据来源。
6. `index.js`:启动时加载 `server/.env`(不覆盖已有 env);Admin POST 配置后触发 `refreshSoon()`(1s 去抖),新数据源不用等 5min 周期。
7. 凭据落地:GLM key 取自 cc-switch 数据库、Kimi key 取自 `~/.claude/settings.json`,写入 `server/.env`(0600);`.gitignore` 补 `server/.env` 与 `server/storage/`。
8. 重启服务并通过 Admin API 写入 codex/zai/kimi 三条配置;拉取 ai 页帧实测:Codex PLUS 97%(本周)/ GLM PRO 9%(每周)/ Kimi 0%,与各家 API 直连结果一致。

### 核心决策

- **每家一个专用适配器而非通用端点**:三家鉴权方式(Bearer / 无 Bearer / 双头+本地登录态)和响应结构差异大,泛化配置救不了;类型白名单把解析逻辑留在代码里,Admin 只配 URL。
- **凭据只走 env(`server/.env`),URL 走 Admin 配置**:延续项目"凭据不进 config.json"约定;codex 完全免配置,直接复用本机 Codex CLI 登录态。
- **codex 刷新 token 后原子写回 auth.json**:OpenAI refresh_token 会轮换,不落盘会导致 Codex CLI 下次刷新失败掉登录;写回时保持 0600。
- **主百分比取所有窗口的最大值**(最紧的约束),明细行展示各窗口,避免 5h/周两个数抢一个主位。
- **配置变更后 `refreshSoon()` 去抖刷新**:todos 本来就是实时读,其余源此前要等最长 5 分钟,现在 1s 内上屏。
