# 2026-09-05 M4 多页面框架（服务端多页渲染 + 客户端分页缓存与翻页）

## 做了什么

在 M2 收尾之后推进 Milestone 4（多页面）中不依赖真机的部分，服务端与客户端各占一半：

**服务端**：
1. `renderer.js` 导出页面清单 `PAGES = [home, calendar, ai, servers, agents]`（顺序即翻页顺序）；`renderFrame` 按页面分发：`home` 保持原布局，`calendar` 为**真实月历页**（当月网格、星期表头、今日反白圆块高亮），其余页为大标题占位页（含"第 N / 5 页"提示便于真机验证翻页）。顶栏（含 PAGE 角标）与底栏各页共用。
2. `index.js`：`status` 响应新增 `pages` 数组供客户端预取；`?page=` 校验收紧为仅接受 PAGES 内的值，未知页面名回退 home。

**客户端（MainActivity.kt）**：
1. 分页缓存：每页独立缓存文件 `frame_<page>.png` 与版本号（`last_version_<page>`），临时文件 `frame_next_<page>.png` 校验后原子替换（原单页原子替换策略逐页沿用）。
2. 页面清单跟随服务端：status 下发的 `pages` 持久化；当前页不在清单时回退首页。
3. 翻页：`switchPage(±1)` 循环翻页，先切本地缓存立即显示再触发刷新按需拉新；触屏左 1/3 上一页、右 1/3 下一页、中间 1/3 刷新（大点击区）；实体键 KEYCODE_PAGE_UP/DOWN(92/93) 与 DPAD 左右(21/22) 映射翻页（BOOX 真实 KeyCode 真机采集后如有出入再补，LeafKeys 全量日志保留）。
4. 版本推进时静默预取其余页面到本地，翻页可离线即时切换；后台预取页只落盘不贴图，不扰动当前画面。

### 核心决策

- calendar 页做真实现而非占位：月历数据纯服务端可算，不依赖外部数据源，是第一个有实际信息量的第二页。
- 页面清单以服务端 status 下发为准（客户端持久化兜底），新增页面无需改客户端。
- 翻页键先用标准键码（92/93/21/22）占位，真机采集 BOOX KeyCode 后再校准；LeafKeys 日志全量保留。
- 预取失败不影响结果判定，仅日志，避免单页网络抖动触发整体失败提示。
