# 2026-09-06 按审核报告修复(P0/P1/P1.5/P2)

## 做了什么

按《leaf-dashboard 代码审核报告 2026-09-06》完成第一批修复(第 1-11 项)+ P1.5 安全(12-13)+ P2 的 configVersion(15)与 CI(16):

**P0**
1. `solarlunar` 补进 `server/package.json`/`package-lock.json`(此前误装到根目录,干净环境 `npm ci` 会启动失败;根目录误生成的 package.json 已删)。
2. Dockerfile:`COPY public ./public`;预创建 `/app/storage/frames` 并 chown 给 node 用户(建议部署时挂持久 volume)。

**P1(Runtime)**
3. 远程 Refresh:`forceReload = remoteRefresh && page == currentPage`,即使 version 未变也强制重拉当前页。
4. Remote Full Refresh:`dueFull = remoteFull || (currentUpdated && (阈值/周期))`——远程全刷不再依赖画面变化。
5. 数据源缓存失效:`refreshSoon()` 现在清空全部 TTL cache 与 lastGood,配置变更后 1s 级生效且无旧配置串数据。
6. Calendar:`parseIcs` 只收 `[now, horizon]` 事件,历史事件不再出现在"近 7 天"。
7. 探活判定:`up = res.ok`(2xx),带 status;404/500/503 一律 Down。
8. `.env` 加载移到 `initStore()/startBackgroundRefresh()` 之前,首次快照即可用 ZAI/KIMI key。

**P1(页面收口)**
9. `PAGES` 收口为四页:`home / calendar / ai / system`;servers+agents 探活合并为 system 页(两节布局+汇总行);persistFrames 自动清理已下线页面残留 PNG。
10. Admin Preview 修复:指向静态 `api/device/frame/<page>.png`;远程控制按钮收口四页。

**P1(客户端)**
11. Frame 缓存迁移到可靠持久目录 `filesDir/frames`,并自动迁移旧 cacheDir 数据(0.2.0 前 cacheDir 根与 frames 子目录两种旧布局)。

**P1.5(安全)**
12. SSRF 补齐:所有出站请求(含探活)改为 `new URL` 解析 → 协议/主机名文本校验 → **DNS 解析全部 A/AAAA 记录逐个确认非私网(防 rebinding)** → `redirect: manual` 逐跳重新校验(最多 3 跳);urlguard 导出 `isPrivateAddress` 供 DNS 结果判定。
13. deviceId 统一白名单化(manifest/status/frame/heartbeat/refresh 全端点);心跳的 currentPage 也过 PAGES 白名单。

**P2**
14. `configVersion` 改为设备相关配置(排除 todos)的 SHA256 内容 hash 前 8 位——进程重启不变、内容变更自动变化。
15. 新增 GitHub Actions CI:`.github/workflows/ci.yml`(server: clean npm ci + 全源语法检查 + 渲染冒烟 + 启动/healthz/manifest/frame 探测;android: assembleDebug + APK artifact)。
