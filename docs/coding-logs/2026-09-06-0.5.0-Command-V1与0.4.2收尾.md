# 2026-09-06 Leaf Dashboard 0.5.0 — Command V1 + 0.4.2 工程收尾

## 做了什么

按《Leaf_Dashboard_0.4.2_to_1.0_Roadmap》完成 0.4.2 工程收尾与 0.5.0 的 Sprint A/B/C:

**0.4.2 工程收尾**
1. CI Android job `fetch-depth: 0`(versionCode/BUILD_COMMIT 由完整 git 历史推导,本地与 CI 一致)。
2. Admin 设备表 App 列显示 `版本 · buildCommit · 机型`。
3. 版本号 0.4.2(Hardware Validation RC);BOOX 能力遥测(`booxPartialAvailable`/`booxFullAvailable`,Discovery 级判定)。

**0.5.0 Sprint A — Command Store + API(服务端)**
4. 新增 `src/commands.js`:命令存储(`storage/commands.json`),状态机 PENDING→SENT→RECEIVED→SUCCEEDED/FAILED(+EXPIRED 过期清理),per-device seq 单调,创建/ACK 即时落盘(不用节流——"设备离线期间命令不能消失")。
5. API:`POST /api/admin/devices/:id/commands`(类型白名单四类)、`GET /api/admin/devices/:id/commands`(最近 8 条历史)、`POST /api/device/:id/commands/:commandId/ack`(received/succeeded/failed,终态幂等)。
6. manifest 增加 `commands[]`(id/seq/type/payload/createdAt/expiresAt,最多 10 条按 seq 升序;携带后标 sent)。旧字段 desiredPage/refreshSeq/fullRefreshSeq 保留——legacy 0.4.x 客户端忽略未知 commands 字段, Capability Negotiation 通过心跳 `capabilities` 数组上报(现含 commands-v1)。

**0.5.0 Sprint B — Android CommandProcessor + Ledger**
7. 新增 `command/CommandLedger.kt`:幂等台账(filesDir/cmd_ledger.json,~100 条,重启存活);台账命中的重复下发不执行、按记录重发 ACK。
8. `processCommands()`:page.switch(切缓存+同步)/device.refresh(强制重拉当前页,忽略 version)/device.full_refresh(乐观台账→整刷完成回调)/sync.restart(500ms 后重新 pollOnce);过期命令 ACK failed;ACK 失败仅记日志(At-least-once 重发兜底)。
9. `performEinkFullRefresh` 增加 onComplete 参数——full_refresh 命令在整刷真正完成后 ACK。

**0.5.0 Sprint C — Admin Command UI**
10. 远程控制区改为统一命令下发(四页按钮/刷新/全刷/重启同步),新增命令历史列表(时间+类型+状态,30s 刷新);旧 desired-page/refresh 端点保留服务端兼容,UI 不再使用。

### 核心决策

- manifest 无条件携带 commands[](0.4.x 旧客户端忽略未知字段),Capability 经心跳上报供服务端后续网关切换,避免首轮同步丢命令。
- full_refresh 台账乐观记录 succeeded(回退实现必然完成),300ms 窗口内重复下发幂等命中。
- 命令持久化即时写盘(不用节流):ACK 幂等重发已防重复写,创建/ACK 低频。
