# 2026-09-06 第四轮审核修复七项

## 做了什么

1. **desiredPage 切页回 UI 线程**:`checkAndUpdate` 运行在 IO executor,远程切页的 `showCachedFrame`(操作 ImageView)改经 `runOnUiThread`。
2. **fullRefresh 完成回调**:接口签名增加 `onComplete: () -> Unit`(保证触发且仅一次)。Generic 在"白→黑→内容"最后一步内容帧贴出后回调;Boox 专有 API 同步语义返回即回调;回退链路透传。
3. **display 与 refresh 解耦**:full 回退恢复内容帧走 `showCachedFrame(page, triggerPartial = false)`,不再触发 partial/计数/策略覆盖——整刷后 strategy 保持 "full",partial 计数不被污染。`showBitmap(bitmap, triggerPartial)` 支持该语义。
4. **lastError=null 真正清除**:客户端心跳对 null 用 `JSONObject.NULL` 显式发送;服务端 storage 对 `lastError` 特殊放行 null 覆盖(其余字段仍跳过 null)。E2E 实测:置错误 → lastError='连接超时';发 null → lastError=None。
5. **syncAttempt 发起前 +1**:移到 `httpGetJson` 调用之前,失败同样计入 attempt。
6. **Partial counters 统一进 `performPartialRefresh()`**:total/sinceFull/策略标记集中维护;`showBitmap(bitmap, triggerPartial)` 与 `switchPage` 都走它;sync 侧的原计数块删除(避免与显示路径双计)。
7. **BootReceiver exported=false**:仅接收系统受保护广播,无需对外暴露。

### 核心决策

- dueFull 阈值判定改读显示路径维护的 sinceFull(可能滞后一次展示,单设备场景无影响),消除双计数。
- 跨 origin + Authorization 组合维持直接拒绝(上一轮已实现,本轮无变化)。
